Two hardening fixes for the helpers that talk to the network: album art now reaches the shell only as a small, clean picture, and the lyrics helper no longer reads a redirect's body. Nothing changes in how the panel looks or works for ordinary covers.

**Update** with `omarchy plugin update crmne.lyrics`, or install with `omarchy plugin add https://github.com/crmne/omarchy-lyrics.git --enable --yes`.

## Fixed

- **A hostile cover can no longer exhaust the shell's memory while it is decoded.** The 16 MiB download limit bounded the file, not what Qt spends decoding it inside the shell: a small PNG can declare billions of pixels, or carry compressed text and colour profiles that inflate to gigabytes. The album-art helper now accepts only PNG and JPEG covers up to 3072 pixels a side, checks that a PNG's pixel data inflates to exactly what its size needs, and rewrites every cover without its metadata before the panel loads it. Covers players keep on disk go through the same check, since they are often files a browser saved from a web page. By @crmne; thanks @HANCORE-linux for the report.
- **A redirecting lyrics server can no longer grow the lyrics helper without limit.** Python's standard library reads the whole body of a redirect before following it, before the helper's own size limits apply. The helper now closes that response first, as the album-art helper has since v1.2.8. By @crmne; thanks @HANCORE-linux for the report.

## Known limitations

- Covers larger than 3072 pixels a side, and covers in formats other than PNG and JPEG (such as GIF or WebP), are no longer shown. The lyrics are unaffected.
- Colour profiles are dropped along with the rest of the metadata, so a wide-gamut cover may look slightly less saturated in the small header thumbnail.
