Fixes for the widget and its commands: the panel opens from `omarchy-shell` commands, the widget finds its service however the shell loads them, and a setting saved as text is read correctly.

**Update** with `omarchy plugin update crmne.lyrics`, or install with `omarchy plugin add https://github.com/crmne/omarchy-lyrics.git --enable --yes`.

## Fixed

- **`toggle`, `show`, and `hide` work, and `status` tells the truth.** These commands returned "ok" without opening the panel on Quickshell 0.3.1. They now open it on the focused monitor and close it everywhere, and with two monitors, one widget giving way to another no longer reads as closed. By @crmne, based on the diagnosis and [#3](https://github.com/crmne/omarchy-lyrics/pull/3) by @mengdream; fixes [#2](https://github.com/crmne/omarchy-lyrics/issues/2), reported by @mengdream.
- **The widget keeps looking for its service when it loads first.** A service that registered after the widget left it without media and without space on the bar, with nothing logged. It now keeps asking, and warns once if the service never answers, which also covers custom bars, where the shell withholds plugin services. This fits part of [#22](https://github.com/crmne/omarchy-lyrics/issues/22), reported by @windy664, but is not confirmed as its cause, so that issue stays open. By @crmne.
- **"Hide when nothing is playing" works when set from the command line.** `omarchy bar set crmne.lyrics hideWhenIdle true` stores the text "true", which was read as off, so the widget stayed on the bar while idle. By @crmne.
